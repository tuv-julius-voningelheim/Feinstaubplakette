The plugin automatically scans your source code, detects only the icon names and styles actually used (`<ts-icon>`, `<TsIcon>`, `<ts-icon-button>`, `<TsIconButton>`), and copies only those SVGs to the build output. No extra dependencies needed.
        - **New export `@tuvsud/design-system/webpack`** — add `designSystemIconsWebpackPlugin()` to your custom webpack config for Angular webpack-based projects. Requires optional peer dependency `copy-webpack-plugin`.
        - ⚠️ **Breaking change**: Add designSystemIconsVitePlugin() to your Vite config or designSystemIconsWebpackPlugin() to your webpack config. Otherwise, icons will not be copied to the production build output and will not render.

    # Version 1.24.0
    - <strong>⚠️ Breaking Changes</strong>
    - <strong>`<ts-icon>`</strong> & <strong>`<ts-icon-button>`</strong>
        - The icon component is no longer connected to the Google Icons library automatically. The library must be downloaded and registered manually in each project. Please refer to the [Setup Icons](?path=/docs/foundation-icons--docs) for setup instructions.
        - **Why?** The previous implementation fetched the Google Material Icons SVG library directly from Google's servers at runtime. This caused Google to receive the end user's IP address on every page load, which is a violation of **GDPR** compliance requirements. To ensure data privacy, the google icon library must now be downloaded in your project with npm.
        - The `style-type` property has been removed. The library registers icons using rounded as the default style. There is no need to specify a style type anymore and the attribute can be safely removed from your code.
